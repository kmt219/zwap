# Local development setup

This guide is based on the captured source, not a completed installation. No build, database migration, wallet transaction or Zcash payout was run during the import.

## Requirements

- Bun 1.2.23, as declared in root `package.json`.
- A Node runtime supported by Next.js 16.
- Docker with Compose for the supplied PostgreSQL 15 container.
- For later Solana-program work only: Rust, Solana CLI and Anchor 0.32.1. They are not required just to inspect the UI source.

## 1. Install dependencies

From the repository root:

```bash
bun install
cp .env.example .env
cp apps/web/.env.example apps/web/.env.local
```

On PowerShell, use `Copy-Item` in place of `cp` if desired. Review dependency install scripts before running them in a sensitive environment.

## 2. Configure a local database and demo-only UI

The Docker file creates a local development database named `zwap` with user `zwap` and password `zwap_dev_password`. These are public example credentials, not suitable for a deployed database. The root `.env.example` uses different placeholders, so replace its database URL.

Set in root `.env` and `apps/web/.env.local`:

```dotenv
DATABASE_URL=postgresql://zwap:zwap_dev_password@localhost:5432/zwap
```

Also set in `apps/web/.env.local`:

```dotenv
DEMO_MODE=true
NEXT_PUBLIC_DEMO_MODE=true
USE_LIVE_RATES=false
AUTO_GEN_ZADDR=false
NEXT_PUBLIC_SOLANA_RPC_URL=https://api.devnet.solana.com
```

Do not place private keys or RPC secrets in a `NEXT_PUBLIC_` variable. Keep `.env` files untracked.

The DB CLI reads root `.env`; Next.js reads its app-local environment. Turbo normally filters environment variables, so the launch command below uses `--env-mode=loose`. This is a local-development convenience, not a production environment policy.

## 3. Start PostgreSQL and apply the schema

```bash
docker compose up -d
docker compose ps
bun run db:push
```

`db:push` changes the configured database. Confirm it points to your local disposable database first. Older supplied scripts use the legacy `docker-compose` executable; the manual commands here use current `docker compose` syntax.

## 4. Start the frontend

```bash
bun run dev:web --env-mode=loose
```

Open http://localhost:3001. The port is declared in `apps/web/package.json`.

Do not start `bun run relayer` for this demo-only setup. The demo branch skips sending a Solana transaction after the backend returns `demo_mode: true`, but the UI still asks for wallet connection and a signature for its sign-in flow. Use a disposable Devnet wallet, inspect every wallet prompt and reject any unexpected transaction.

Demo address generation currently returns `demo-zaddr-...`, while the deposit input validation requires a `z` or `u1` address. This mismatch can block the generated demo-address path. Do not fix that by supplying a funded destination or switching to mainnet. Treat it as an application issue to resolve separately.

The simulator stores phase information in memory. Restarting the process can lose that phase state even though database rows remain.

## Optional modules

- Receipts require an Ed25519 signing key configured server-side as `SIGNING_KEY_PEM` (or `SIGNING_KEY`). `SIGNING_PUBKEY_PEM` is used for verification. No key is supplied or generated by this import.
- The standalone relayer validates `ZCASH_RPC_PASSWORD`; the API address-generation client reads `ZCASH_RPC_PASS`. If reviewing both paths, account for both names and the same intended RPC identity.
- `USE_LIVE_RATES=true` enables selected live fee/metrics paths, not a verified live exchange-rate or settlement system.

## Troubleshooting

| Symptom | First check |
| --- | --- |
| Database login fails | Match the Docker credentials and ensure PostgreSQL is healthy |
| UI ignores demo settings | App-local `.env.local`, restart Next.js, launch Turbo with loose environment mode |
| Browser cannot connect | Dev server uses port 3001; inspect terminal output |
| Anchor build fails | Check Anchor 0.32.1 and the Rust/Solana toolchain separately |
| Zcash auth fails | Check which client reads `_PASS` versus `_PASSWORD`; never log the values |
| Address rejected | Demo generator and deposit validator have incompatible formats in this snapshot |

The old setup and completion notes are retained as upstream historical material. They do not prove services are running now.
